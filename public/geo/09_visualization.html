GEO Microarray Analysis 과정 목차
Step 09

GO·KEGG 분석과 입력자료 준비

차등발현유전자 목록을 생물학적 기능과 pathway로 해석하기 위한 원리와 입력자료를 준비합니다.

왜 기능분석을 수행하는가?

DEG 분석은 어떤 유전자가 변했는지를 알려주지만, 질환에서 어떤 생물학적 과정이 함께 변했는지는 유전자 목록만으로 파악하기 어렵습니다. 기능분석은 여러 DEG가 공통으로 참여하는 기능이나 pathway를 통계적으로 요약합니다.

DEG→ Gene ID 정리→ GO·KEGG→ 생물학적 가설
기능분석은 결과를 자동으로 설명해 주는 과정이 아닙니다. 유의한 term과 pathway를 연구 설계, 조직, 질환과 기존 지식에 연결하여 해석해야 합니다.

1. GO란?

Gene Ontology(GO)는 서로 다른 연구와 데이터베이스에서 유전자 기능을 일관된 용어로 설명하기 위한 체계입니다.

분류질문예
BP
Biological Process		유전자가 어떤 생물학적 과정에 참여하는가?immune response, cell cycle, apoptosis
CC
Cellular Component		유전자 산물이 세포의 어디에 존재하거나 작용하는가?nucleus, mitochondrion, extracellular matrix
MF
Molecular Function		유전자 산물이 분자 수준에서 어떤 기능을 수행하는가?kinase activity, DNA binding, receptor binding
GO term은 계층구조입니다. 상위의 넓은 term과 하위의 구체적인 term이 같은 유전자를 공유하므로 유사한 결과가 반복해서 나타날 수 있습니다.

2. KEGG pathway란?

KEGG는 대사, 신호전달, 질환과 세포 과정에 관련된 유전자·단백질의 관계를 pathway 형태로 정리합니다.

GOKEGG
유전자 기능을 표준 용어로 분류유전자 간 기능적 관계를 pathway로 구성
BP·CC·MF의 계층구조대사·신호전달·질환 pathway 중심
유사하거나 중복된 term이 많을 수 있음하나의 유전자가 여러 pathway에 포함될 수 있음
KEGG pathway가 유의하다고 pathway 전체가 활성화됐다는 뜻은 아닙니다. 입력한 DEG가 해당 pathway에 기대보다 많이 포함되었다는 의미이며, 방향성과 구성 유전자를 별도로 확인해야 합니다.

3. ORA의 기본 원리

Over-representation analysis(ORA)는 선택한 DEG 목록에 특정 GO term 또는 pathway 유전자가 background에서 기대되는 비율보다 많이 포함되어 있는지를 검정합니다.

특정 pathway 포함특정 pathway 미포함
DEG관찰된 DEG 수나머지 DEG
Background의 비-DEGpathway의 비-DEG나머지 유전자

일반적으로 Fisher’s exact test 또는 동등한 hypergeometric test를 사용하며, 여러 term을 동시에 검정하기 때문에 결과의 FDR을 확인합니다.

ORA의 입력은 두 가지입니다. 관심 유전자 목록(DEG)과 그 유전자들이 선택될 수 있었던 전체 background입니다.

4. Up과 Down을 분리하는 이유

up_symbols <- unique(
  deg$gene_symbol[deg$status == "Up"]
)
down_symbols <- unique(
  deg$gene_symbol[deg$status == "Down"]
)

Up과 Down을 합치면 특정 기능과 관련된 유전자가 DEG에 많다는 사실은 알 수 있지만, 그 기능이 Disease에서 어느 방향으로 변했는지는 잃게 됩니다.

입력해석
Up DEGDisease에서 증가한 유전자에 과대표현된 기능
Down DEGDisease에서 감소한 유전자에 과대표현된 기능
Up + Down방향을 구분하지 않은 전체 DEG의 관련 기능
ORA만으로 pathway 활성·억제를 확정하지 않습니다. Up ORA와 Down ORA의 분리 결과, pathway 구성 유전자와 후속 GSEA의 NES 방향을 함께 검토합니다.

5. Background가 중요한 이유

Background는 DEG가 선택될 수 있었던 전체 유전자 집합입니다. Microarray 분석에서는 해당 플랫폼에서 실제로 측정되고 전처리와 annotation을 통과한 유전자를 사용하는 것이 원칙적으로 더 적절합니다.

background_symbols <- sort(unique(
  probe_map$gene_symbol[
    probe_map$probe_id %in% deg$PROBE_ID
  ]
))
Background문제 또는 장점
전체 인간 유전체Microarray에서 측정되지 않은 유전자까지 포함되어 enrichment가 편향될 수 있음
플랫폼의 모든 annotation 유전자실제로 분석에서 제거된 probe가 포함될 수 있음
실제 분석된 유효 probe의 고유 유전자현재 DEG가 선택될 수 있었던 범위와 가장 직접적으로 대응

6. 여러 probe가 같은 gene에 대응하는 문제

ORA의 단위는 일반적으로 gene이므로 하나의 gene symbol이 여러 probe에서 DEG로 나타나도 입력 목록에는 한 번만 포함합니다.

up_symbols <- sort(unique(
  stats::na.omit(up_symbols)
))

동일 gene의 일부 probe는 Up, 다른 probe는 Down으로 분류될 수 있습니다. 제공 스크립트는 이런 gene을 opposite_direction_probe_conflicts.csv에 기록하고 입문 ORA의 Up·Down 목록에서는 보수적으로 제외합니다.

반대 방향 probe는 오류라고 단정할 수 없습니다. 서로 다른 transcript, probe 위치, cross-hybridization 또는 품질 문제일 수 있으므로 중요한 후보는 플랫폼 annotation과 probe-level 결과를 확인합니다.

7. Gene symbol과 Entrez ID

DAVID와 pathway 도구는 여러 identifier를 지원하지만, identifier 종류를 명확히 지정해야 합니다. 이번 스크립트는 human gene symbol을 org.Hs.eg.db로 Entrez ID에 변환합니다.

converted <- AnnotationDbi::select(
  org.Hs.eg.db,
  keys = up_symbols,
  keytype = "SYMBOL",
  columns = "ENTREZID"
)
현상의미처리
Symbol이 Entrez로 변환되지 않음옛 symbol, 비표준 ID, lncRNA 또는 annotation 차이원 ID와 mapping report 확인
하나의 symbol에 여러 Entrez ID일대다 mapping임의로 첫 ID만 고르지 않고 변환표에 모두 기록
여러 symbol이 같은 Entrez ID동의어 또는 annotation 변경 가능성Entrez 입력에서는 중복 제거

8. FDR 유의 DEG가 없을 때

GSE54568처럼 표본 변동이 크거나 효과가 작으면 FDR 기준을 통과하는 DEG가 없을 수 있습니다. 이 경우 빈 gene list가 생성되는 것은 코드 오류가 아니라 분석 결과입니다.

결과를 만들기 위해 cutoff를 임의로 완화하지 않습니다. 탐색적으로 raw P-value 목록을 사용할 수는 있지만 FDR 유의 DEG와 구분하여 표시해야 하며, 확인적 ORA의 근거로 과도하게 해석해서는 안 됩니다.

명확한 DEG cutoff가 없거나 많은 유전자가 작은 방향성 변화를 보이는 경우에는 전체 유전자 순위를 사용하는 Step 12의 GSEA가 더 적절할 수 있습니다.

종합 실습

  1. GO BP·CC·MF와 KEGG pathway의 차이를 각각 한 문장으로 설명합니다.
  2. Up·Down DEG의 고유 gene symbol 수를 계산합니다.
  3. 동일 gene symbol이 Up과 Down에 모두 포함되는지 확인하고 관련 probe를 조사합니다.
  4. 분석 background를 전체 인간 유전체가 아니라 현재 microarray의 분석 유전자로 정의합니다.
  5. Gene symbol을 Entrez ID로 변환하고 목록별 mapping rate를 계산합니다.
  6. 변환되지 않은 유전자를 찾아 원래 probe annotation을 확인합니다.
  7. DAVID에 사용할 identifier와 species를 기록합니다.
  8. 유의 DEG가 없다면 ORA를 수행할지, GSEA로 넘어갈지 근거를 작성합니다.
